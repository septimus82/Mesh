# Milestone 5: visual event authoring — results and notes

Branch `redesign/visual-editor`. Summary and status: [`MESH_REBUILD.md`](../../MESH_REBUILD.md).

The question this milestone answers: **can a person build a small, conditional, animated,
dialogue-driven scene entirely in Mesh Studio?** In the Ezekiel cemetery test the runtime could
already play such a scene, but its objects, animation and dialogue had to be written by an AI
through `project_ops`. Now the Studio writes them, through the same operations.

## Graphical acceptance test

`py -3.13 tooling/acceptance_event_authoring.py --out DIR` (Windows).
- `MESH_GUI_AT=x,y` places the window, e.g. on a second monitor.
- `MESH_GUI_POLITE=3` waits whenever someone uses the mouse.

How it works:
- A fresh **Blank** project is made with `mesh new` (setup only).
- Everything after that is done in the Studio window with OS-level mouse and keyboard input. That includes the Windows file picker for importing pictures.
- The Studio's layout dump is read only to find things and to check state. Saved files are only read, to check what was written.
- The art is generated by the test: a 3×4 walking character, a shovel, a grave closed and dug open, and a gravekeeper. No third-party art is in the repository.

## What the Studio can now author

| Inspector tab | What you do | Written as (existing runtime data) |
|---|---|---|
| Look | Import or choose a picture (project picture browser), size, mirror | `sprite`, `scale`, `flip_x` |
| Animation | 4-direction walking from a sheet; clips (row, frames, speed, mirror); live preview; starting facing | Animator `animations` + `directional_mode: 4-way` |
| Collision | Blocks movement; whole picture / footprint / circle with map handles; trigger zone with a handle, "start its conversation", "set flags", once | `solid`, `components.collider`, TriggerVolume + Dialogue `start_event` + SetGameStateOnEvent |
| Dialogue | Lines, speakers, flow, choices with **Requires** / **Not if** / **Sets** / **Clears** flags and **Counts up**, openings by flags, only-once, starts by itself, tester | Dialogue graph (`nodes`, `choices`, `starts`) |
| Conditions | **Show when**, **Can be talked to when**, **Looks different when**, each with a **Pick** list of the project's flags | ConditionalActivator, Dialogue `require_flags`/`forbid_flags`, PictureByFlags |
| Behaviours | Every behaviour; list and object settings as checked text (JSON) | `behaviour_config` |

Also:
- **Objects list:** **Empty object** and **Trigger zone**.
- **Flags** (top bar): every flag, and where it is set or checked.
- **Flags while playing:** see and flip flags; counters are shown.
- **Closing with unsaved work:** asks Save / Discard / Cancel.
- **"Show when" objects:** drawn see-through while editing.

## Engine changes

**Reused:**
- Animator;
- the Dialogue graph;
- ConditionalActivator;
- TriggerVolume;
- SetGameStateOnEvent;
- `components.collider` physics;
- the save and quick-save system;
- `project_ops` as the only way the Studio edits.

**Small runtime additions,** each closing a real gap:
- Dialogue **`starts`**: opening lines chosen by flags.
- Animator clip **`flip_x`** and entity **`flip_x`**: there was no horizontal flip anywhere.
- **`PictureByFlags`**: the existing appearance swaps were not working.
- Collider kind **`box`**: a footprint, honoured for objects that move and objects that block.

**Fixed at the source:**

| Fix | Why |
|---|---|
| y-sort draws what stands lower on screen in front, compared at the feet | It was inverted for arcade's y-up, so a dug grave was drawn over Ezekiel's head |
| The interact prompt fits its label | Long labels spilled off the screen's left edge |
| Hidden ConditionalActivator objects stop blocking | They kept blocking |
| Sprites get `mesh_tags` and `mesh_id` | Every `target_tags` filter matched nothing, so trigger zones could never see the player |
| A crash leaves evidence | The last log is kept, and a message names it |

**Studio code:** the inspector is one module (`engine/studio_inspector.py`), one tab builder per
section, all using the same field, toggle and flag-picker helpers. It is not one controller per
feature. The right panel scrolls generically.

## What still needs code or the API

- **Origins/anchors:** sprites are centred, and there is no origin setting in the runtime.
- **Counter conditions:** counters can be counted up, but nothing in the runtime can require "graves_dug ≥ 3". Flags gate everything. The cemetery used three flags for its three graves.
- **Multi-step event sequences without a conversation**, such as wait / move / play a sound. `ActionListRunner` exists, but its action list is only editable as JSON text in the Behaviours tab.
- **Quest and item editors,** which were deliberately deferred.
