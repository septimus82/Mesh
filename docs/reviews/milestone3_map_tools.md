## The "ignored start-up clicks" investigation

- **Logging added.** The Studio now logs the first three mouse presses the window receives, with the time since start (`[Mesh][Studio] mouse press N at T s`). If clicks are lost at start-up, the log shows whether they reached the app at all.
- **No lost click since.** None occurred in this milestone's runs: 11 GUI runs of the three acceptance tests, plus probes.
- **A different intermittent failure, now explained.**
  - One Milestone 2 run painted a curved trail of floor tiles off the end of a stroke. A palette click in the same run turned into a two-row drag.
  - The driver's own drags are straight lines, so this points to the physical mouse moving during the run.
  - The GUI driver now records where it put the pointer and stops the test if it has moved before its next action ("keep hands off the mouse while a GUI test runs"). It stopped two later runs this way. Retrying with the mouse untouched passed.
- **Not proven: the start-up drops.** Mouse movement during the first clicks could explain those too, but that is not proven. If the editor ignores the first clicks for you by hand, the new log lines will tell us whether the clicks reached it.

## Implementation notes

- **No new formats or systems.**
  - Imported tilesets are standard Tiled tileset JSON files next to their PNG in `assets/tilesets/`.
  - Every room's Tiled map file lists them under `tilesets`. Import appends with the next free first gid, so tile ids already painted keep their meaning.
  - Tiles are still stored in the scene's inline `tile_layers`. All edits still go through `engine/project_ops.py`:
    - `paint_tiles` now takes a stamp and an anchor; brush, rectangle and fill all use it, and erasing paints 0.
    - New: `rect_cells`, `fill_cells`, `tileset_document`, `map_tilesets`, `with_tileset`, `paste_entity`.
  - Fill reuses the engine's existing `engine/tilemap_flood_fill.py` (until now used only by the CLI).
- **Alignment.**
  - The runtime places each tile sprite at its cell's centre at scale 1, so tiles larger or smaller than the map's 32 px would not line up.
  - Import therefore cuts the image to whole tiles and scales them to 32 px: nearest-neighbour when enlarging (pixel art stays crisp), Lanczos when shrinking.
  - The copy goes into the project, so asset paths are always project-relative.
  - Importing is not undoable: it writes files, and an unused tileset is harmless.
- **The above-player layer.**
  - It is a third tile layer, `overhead`, with `z: 10, collision: false`. The runtime already draws tile layers with z ≥ 0 after characters, so nothing in the renderer changed.
  - Collision stays a per-layer setting: only `walls` blocks. Painting a tile on "Above" never makes it solid, and painting it on "Walls" always does.
  - In the editor the overhead layer is drawn see-through unless "Above" is the active layer, so roofs don't hide what you are working on.
- **Runtime fix.** A layer present in the scene's inline tiles but missing from the map file used to be dropped. It now loads from the scene's tiles alone (`3f20796`). Rooms made in Milestone 2 gain the overhead layer without rewriting their map files.
- **Palette.**
  - The palette is the tileset image itself, drawn as a grid. Click a tile, or drag across several to make a stamp. Scroll it with the mouse wheel (Shift for sideways).
  - Starter tiles still carry a suggested layer, so picking a wall switches to Walls. Imported tiles keep whatever layer you have chosen.
- **Clipboard.**
  - Text fields handle Ctrl+A, C, X and V themselves, using pyglet's system-clipboard access; arcade's text fields have none. Fields are single-line, so pasted line breaks become spaces.
  - Objects: Ctrl+C copies the selected object, and Ctrl+V pastes it at the mouse in any room. The right-click menu also offers Copy and "Paste ... here". The player and arrival spots can't be copied.
- **Eyedropper.** Right-click the map → "Paint with this tile" picks the topmost tile in that cell, along with its layer.

## Legacy editor: what the Studio still lacks

Before retiring anything, the legacy editor and Creator Mode were inventoried (36 user-facing capabilities). Status in the Studio after this milestone:

**Covered:**
- Rooms and doors
- Placing objects
- Behaviour settings (scalar fields)
- Tile painting: own tilesets, three layers, brush, rectangle, fill, eyedropper and stamps
- Copy/paste of objects
- Undo/redo
- Play-testing

**Still missing:**
1. **Quest, item and prefab editors.** Without them, a game can only use the quests, items and object types that ship.
2. **Full dialogue editing.** The Studio edits the first line only; there are no pages or choices.
3. **Editing list and object settings.** A generic list editor would cover game-state flags, patrol waypoints, shop stock, inventories, drop tables and animation clips.
4. **Triggers and zones drawn and resized on the map.** Today they are numbers in the inspector.
5. **Sprite and collider fields in the inspector,** and opening scenes that aren't rooms of a world.

**Useful but not blocking:**
- An outliner (object list)
- Multi-select
- Scene lights
- Parallax planes
- A problems panel
- An asset browser
- Grid and nudge controls

Neither editor yet edits map size, camera bounds or scene music.
