## 3. Dependencies and coupling

- **Declared runtime dependencies are minimal:** `arcade`, `jsonschema`, `pillow`, all used.
  - The optional extras (`mcp`, `chat`, `chat-local`) are behind import guards.
  - `referencing` is imported directly but comes with `jsonschema` (minor: declare it).
  - `PyInstaller` is used only by `tooling/build_game.py` and not declared (dev tool; fine, but say so in the docs).
- **Import cycles at module top level:** 8 small cycles.
  - The largest (7 modules) is the input capture routing: `input_runtime`, `capture`, `capture_key_router`, `capture_mouse_router`, `capture_mouse_router_handlers_global`, `capture_runtime`, `dispatch`.
  - These match the known input-dispatch fragility (5+ incidents).
- **Runtime → editor imports (top level):**
  - `engine.game → engine.editor_controller` (so the whole editor loads at every boot);
  - `engine.ai_ops → engine.editor_palette`;
  - `input_runtime.capture_focus_query → editor.editor_panels_query`.
  - The render path's editor dependency was removed in Milestone 7.
- **Runtime → monster imports:**
  - `engine.game → monster.battle_mode`;
  - two behaviours (`monster_encounter_zone`, `breeding_shrine_zone`) → monster modules.
  - That is the whole coupling the plugin extraction has to cut.
- **Tracked local-state files:**
  - `projects.json` is tracked but no longer read (Milestone 4 moved it to the user profile); a conftest guard fails any test that writes it.
  - `user_settings.json` is tracked; left untouched by standing instruction.
- **Tests writing into the repository:** a few runner tests write small files into the repo's ignored `artifacts/` (`pytest_full.log`, `swallow_scan.json`). Harmless, but they belong in `tmp_path`.
